# Harbourline DMS: 12-minute back-office demo talk track

Continues `docs/DEMO-SCRIPT.md` (the configurator demo). Audience: DMS vendor stakeholders and dealer principals. Presenter speaks in first person. All data is synthetic. Build contract: `docs/DMS-SPEC.md`; requirements: `docs/DMS-PRD.md`.

## Pre-demo checklist

- Run the configurator and DMS from the same server (the DMS lives at `/dms`). Check `/dms/api/health` and `/dms/api/arag/status` show the KB connected. If not, the ARAG beats will show "not connected": do not present them live.
- Reset seed data so the configurator test drive is the newest booking. Do the configurator part (finder, configure, book a test drive for a RAV4 or Kluger at Parramatta, ask one question in the booking flow) immediately before, or pre-book it and note the booking id.
- Log in as `sales1@harbourline.demo` first; keep `sm.par@harbourline.demo`, `finance@harbourline.demo`, `marketing@harbourline.demo` and `gm@harbourline.demo` ready in a second profile or window (password `demo1234`; a reload logs out).
- Pre-warm: run "Process" once on the supplier invoice sample (reset its status after) so you know the timing; ask each demo question once so the retrieval caches are warm.
- Pick the stuck deal in advance (the answer to the Penrith finance question) and have its id handy.
- Browser 1180 px or wider, 100% zoom, light theme. Keep the prototype band visible.
- Have Claude or Cursor open with the KB MCP connected only if you rehearsed it today. Engineering saw the MCP connection fail on 14 Oct; if it fails, use the Settings page and say so.

## What is real versus simulated

| Piece | Status |
|---|---|
| Progress Agentic RAG: ask, find, extraction, drafting, summary, agent | Real when the server has a KB token. The server holds it; the browser never sees it. |
| ERP data (customers, leads, deals, stock, finance, documents) | Synthetic, generated by a seeded script, served from memory. |
| Domo datasets, dashboards, signals | The DMS publishes the exports and derived signals. Domo is a stand-in until a real instance is connected. The in-app Domo cards preview dashboards Revolution would build in Domo. |
| Sending email or SMS, finance lender decisions, Toyota systems | Not connected. Drafts are copied, not sent. |
| Authentication | Prototype logins only. |

## Beat 0: Framing and bridge (0:00-1:00)

- Click: open `/dms`, sign in as `sales1@harbourline.demo`. Point to the band and the rail.
- Say: "That was the showroom. This is the back office of the same made-up dealer group, Harbourline Toyota. Sales only: no service, parts or accounting. Same two technologies underneath: Progress Agentic RAG for knowledge and language, Domo for analytics and decisions. Every AI control is tagged so you can see which is which."
- ARAG: "The tag says Progress Agentic RAG wherever a retrieval or a model is involved."
- Domo: "The tag says Domo, with the dataset name, wherever a number came from the analytics layer."
- If it goes wrong: if login fails, check the password `demo1234` and that the server is the same origin as the configurator.

## Beat 1: The test drive arrives as a lead (1:00-2:30)

- Click: Leads. Open the newest lead (channel: configurator). Scroll to the configurator panel and the handover sheet.
- Audience sees: finder answers, cars viewed, offers clicked, the booking (car, site, time), the question the customer asked, the incentive, the handover sheet.
- Say: "The booking I made a minute ago is already here, owned by Sam at Parramatta. Sam does not start cold: they can see the customer wanted to tow a caravan, looked at the Prado and the Kluger, asked about the Towing Pack, and was offered the first-service incentive. That is the first-party data the configurator captured."
- ARAG: "The questions the customer asked were answered by the knowledge box in the configurator; here they come across with their answers and sources."
- Domo: "The lead score and the offer came from Domo's view of stock and targets, not from a salesperson's gut."
- If it goes wrong: if the live booking is missing, open the pre-booked lead from the checklist and say it was booked earlier.

## Beat 2: Draft the follow-up (2:30-4:00)

- Click: on the lead, "Draft follow-up", tone "Friendly", channel "Email". Show the draft. Then switch language to Vietnamese or Chinese and redraft if time.
- Audience sees: a short email naming the car, the colour, the Towing Pack question; promotion chips showing which real promotions were used; a source list.
- Say: "The draft is built from what this customer actually did. Notice it only mentions the promotion that exists in the register and is in date. It cannot invent an offer. Sam edits, copies and sends from their own mail. Nothing is sent from here."
- ARAG: "Generation with extra context: the lead, the booking and the promotions go in; the dealer policy decides what may be said. In another language it uses the same sources and the same numbers."
- Domo: "The promotion it picked is the one Domo says is worth pushing for this model this week."
- If it goes wrong: if the draft is slow, say retrieval is running live and wait up to 15 seconds; if it errors, say the KB is unreachable and move on.

## Beat 3: The sales manager asks the ERP agent (4:00-5:30)

- Click: sign out, sign in as `sm.par@harbourline.demo`. Assistant, "Ask the ERP". Click the example "Which deals are stuck in finance for more than 5 days at Penrith?". Expand the evidence.
- Audience sees: a plain answer, the evidence rows (deal id, stage, days in stage, salesperson), the tool calls the agent made.
- Say: "Raj does not run a report. He asks. The agent decides which queries to run against the live ERP, runs them, and shows me the rows it used. If I count the evidence rows, they match the answer. If it cannot find something it says so."
- ARAG: "This is Progress Agentic RAG as an agent with tools: it plans, calls erp.search and erp.kpi through the API, then answers from the rows it got back. The knowledge box does the reasoning; the data never leaves the server."
- Domo: "For the numbers questions, such as target attainment, the agent reads the same KPIs that feed the Domo cards."
- If it goes wrong: if the answer returns zero rows, switch to the second example question (deals with no activity for seven days); if the agent is down, show `/dms/api/deals?stage=finance` and say the agent normally does this for you.
- Optional 20 seconds: switch to "Ask the manual" and ask "What do I need before I submit finance with a trade-in?" to show cited policy.

## Beat 4: Deal summary and next action (5:30-7:00)

- Click: from an evidence row open the stuck deal. Click "Summarise".
- Audience sees: timeline, finance application, trade-in; then a summary, a next best action, and risks, each with sources.
- Say: "The deal has thirty events and three documents. Raj gets a paragraph, the one thing to do today, and what could go wrong. The risk it flags comes from our policy: finance is waiting on a trade-in inspection. Click the citation and you land on the policy paragraph."
- ARAG: "Same model, but now the deal record, events, customer, finance application and policy go in as context. It must cite what it used."
- Domo: "The days-in-stage benchmark it compares against is from the funnel dataset."
- If it goes wrong: if the summary is generic, point to the sources panel and say the point is that every sentence maps to a record.

## Beat 5: Process a supplier invoice (7:00-8:15)

- Click: sign out, sign in as `finance@harbourline.demo`. Documents, upload or select the sample supplier invoice, "Process". Open the result.
- Audience sees: the PDF beside extracted fields (supplier, ABN, invoice number, lines, GST, total), a confidence per field, and fields flagged to verify. Click "Verify".
- Say: "Fiona's supplier invoices used to be typed in. The document is ingested, extracted against a schema, and anything the model is unsure about is flagged. A human verifies. We never auto-approve."
- ARAG: "Document processing: the PDF becomes a resource in the knowledge box, then extraction with a JSON schema returns fields and confidence. The same document is now searchable."
- Domo: "Verified invoices become a dataset row that Domo can join to stock cost, so landed cost and gross are right."
- If it goes wrong: use the pre-processed document from the checklist and say processing normally takes under half a minute.
- Optional: use global search "customer unhappy about trade-in value" to show semantic search finding policy and deal notes across sources.

## Beat 6: Stock and Domo's move priorities (8:15-9:15)

- Click: sign in as `gm@harbourline.demo`, Stock, filter Kluger or the model with the highest priority. Open a unit and "Why this is being pushed".
- Audience sees: ageing heat by site, Domo signals per model (days of supply, allocation next month, target gap, margin headroom), a move priority and reason on each unit.
- Say: "Grace sees where stock is ageing and which units are priority one. And the reason is spelled out: sixty-one days in stock, a target gap of six and fourteen units arriving next month, so we have headroom of up to $2,400 to move it. It is not a black box."
- Domo: "This is the loop. The DMS exports its data, Domo models it into dealer_signals, and the same priorities drive the configurator offers we showed earlier. Sell the car and the priority falls on its own."
- ARAG: "Ask the agent 'Why is HL-2150 a priority?' and it explains from the same signals."
- If it goes wrong: if the signals look stale, point to the refreshed time and say Domo refreshes nightly.

## Beat 7: Promotions composed from Domo targets (9:15-10:15)

- Sign in as `marketing@harbourline.demo`. Promotions. Show Domo-selected targets, then "Compose". Review provenance and approve one. Switch to the configurator tab and reload the offers strip.
- Audience sees: targets chosen by Domo, ARAG-composed promotions with value, constraints, validity and provenance, and an approval step.
- Say: "Dev does not write offers from scratch. Domo says which models to move and how much room there is. The knowledge box composes promotions inside the policy: only what the funding allows, with an end date. Dev approves; only approved promotions reach the configurator. A draft cannot leak."
- ARAG: "Composition is grounded in the promotions policy and register; it cannot exceed headroom or invent a promotion type."
- Domo: "Targets and headroom come from dealer_signals and aged_stock_actions."
- If it goes wrong: if compose is slow, approve an already-composed promotion and refresh the configurator.

## Beat 8: Insights and the Domo dataset catalogue (10:15-11:00)

- Click: Insights. Open `dealer_signals`, show schema, row count, CSV link; download one CSV. Open "how to connect Domo". Optionally show the DXM page's configurator report.
- Audience sees: every table and derived dataset with description, refresh, row count, schema and CSV URL.
- Say: "Everything you saw is available as plain datasets. This is how Revolution plugs Domo in: point the connector at these exports, or at your own tables with the same shape. The dashboards on the Dashboard page are what you would build in Domo: sales performance, funnel, stock health, finance, campaign ROI and configurator insight."
- Domo: "Joins are documented. Configurator events, with no personal data, join to leads by session id."
- If it goes wrong: if a CSV does not download, show the schema and say the export is generated on demand.

## Beat 9: Settings, OpenAPI and MCP (11:00-11:45)

- Click: Settings. Open the API docs; show the OpenAPI JSON; show the MCP endpoint and the connect instructions.
- Say: "The app only ever talks to this API. Here is the documentation, generated from the route table. And the knowledge is reachable from outside the app: this is the knowledge box's MCP endpoint, so Revolution's own agents or Claude and Cursor can ask the same question and get the same cited answer."
- ARAG: "MCP turns the knowledge box into a tool any agent can call. The page never shows a token."
- If it goes wrong: if the MCP demo from Claude fails, stay on Settings and say it is the connection to be proven in the pilot.

## Beat 10: Close (11:45-12:00)

- Say: "Back to the beginning: the customer booked in the configurator, Sam called with context, Raj found the stuck deal, Fiona processed the invoice, Grace saw why a car was being pushed, Dev published a promotion that is honest, and the configurator learned from it all. The knowledge and language are Progress Agentic RAG. The data is synthetic. Domo is a stand-in shaped like the real thing. What would you connect first?"
